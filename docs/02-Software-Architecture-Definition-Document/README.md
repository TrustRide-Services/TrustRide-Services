# 02. Software Architecture Definition Document (SADD)

## Purpose

Defines the SADD for this project, per the Engineering Office Project Repository Standard
(`00-FOUNDATION/standards/PROJECT_REPOSITORY_STANDARD.md`).

## Scope

Architectural vision, principles, context, views, components, technology strategy,
non-functional requirements, cross-cutting concerns.

## Contents

**`TRS026-SAPC-001_Master_Instrument`** (md / docx / pdf) — the System Architecture &
Platform Constitution (SAPC), TrustRide's second sovereign instrument, inheriting from TBOC
(`01-Constitution/`) per TBOC Article 58.

Covers: the digital twin doctrine, the identity chain, the five macro domains realized in
architecture, the five presentation shells realized in architecture, the eleven-engine
sovereign registry and the modular-monolith principle, Plate I (the five-station machine
every engine is), Plate II (the five-layer register), Plate III (the surface law) — and an
index of all eleven engines with their table counts, cross-referencing `03-Core-Domain-Model/`
(Foundation) and `04-Platform-Engine-Registry/` (Engines 2–10) and `07-Presentation-Architecture/`
(Engine 11) for full implementation detail.

**Note on this folder's name:** an earlier, informal reference PDF titled "Software
Architecture Definition Document" existed as the Founder's own rough early sketch of the
platform. That PDF was explicitly ruled background inspiration only, never authoritative, and
is not filed here — per the Founder's 2026-08-16 ruling, all prior/informal TrustRide
documentation in this repository is superseded by the finalized, adopted corpus. This folder
holds SAPC, which is the actual, adopted architecture-definition instrument for the platform.

## Dependencies

- `01-Constitution/` — every architectural provision here traces to a named TBOC article
  (SAPC Article 58); no concept originates in this document.
